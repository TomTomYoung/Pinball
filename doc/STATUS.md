## 1. 今回の到達点

編集→保存→読込→プレイ→終了→再プレイ→編集復帰の基本経路を修正し、実Phaser/Matterの14件と実Chromiumの8件、計22件の回帰テストを通しました。単一HTMLを直接開く利用方法は維持し、npm依存はテストにだけ使用します。backup・backup2は変更していません。

修正前の初期調査文書は[history/2026-10-16-before-fix](./history/2026-10-16-before-fix/STATUS.md)に保存しています。

## 2. 修正済みの問題

### P-01: 初期化順

派生値の設定後に物理・描画を生成するよう修正しました。修正前の実エンジン診断では固定壁が60stepでY=200から約621へ落下し、半径10のボールと開始位置マーカーが半径128で生成されていました。修正後は固定壁が静止し、マーカーは非物理・半透明、実ボールは指定半径です。色・反発・摩擦も生成時から一致します。

### P-02: 外周壁

用途をisBoundaryで分離しました。外周3枚は編集・削除・保存から除外し、プレイ時にも3枚だけ生成します。旧形式に混入した外周は確認付きで移行でき、同名のユーザー壁は保持します。

### P-03: 起動・再プレイ

準備前のScene取得を廃止し、sceneインスタンスへapp参照を渡します。restartはScenePlugin経由に変更しました。スコア・物体配列・実ボール・開始位置を毎回作り直します。破棄済みフリッパーにキー操作して例外になる問題も解消しました。実シーンで再プレイ4回と編集復帰、マーカー削除後の再開始を検証しています。

補足: 初期調査で挙げた衝突リスナー蓄積の疑いは、修正前の実ライブラリ診断では確認されませんでした。Phaser側もWorld.shutdownで解除しています。今回の実装では自前の解除と参照破棄を明示し、各再プレイでcollisionstartリスナー1件を確認します。

### P-04: 終了状態

終了を一回に制限し、物理・キーボード・追加得点を停止しました。上部の編集復帰ボタンでも終了表示が残りません。EditorSceneはプレイ中sleepして非表示です。

### P-05: 描画・物理・保存の一致

累積拡縮を廃止しました。修正前は幅200の壁の物理幅が400→800→1600となり、直径40のバンパーの当たり判定幅は約6.2、移動後約0.97でした。修正後は寸法変更時だけボディを作り直し、繰り返し更新・移動で寸法が変わりません。円は半径を正本とし、色編集も反映します。

フリッパーは描画・物理の中心を揃え、端を固定するヒンジと角速度駆動を導入しました。左右で目標角と支点の保持、解除後の戻り、球が上方に加速する実衝突を検証しています。

### P-06: 読込時のデータ消失

構造・型・有限値・範囲を全件検証し、仮生成が成功した場合だけ盤面を置換します。不正JSON、objects欠落、未知型、復元途中例外でも現在の盤面・選択が残ります。保存容量エラーも通知します。旧文字列の初回上書き前には別キーへバックアップします。

### P-07: リサイズ・選択・数値

盤面寸法を保存し、表示は縦横同比率のFITへ変更しました。実ブラウザで縮小後の形状選択とドラッグを検証しています。中心50px判定は円・回転矩形判定へ変更しました。空欄・負の寸法を拒否し、得点0と角度0を保持します。

### 追加で修正した問題

実ブラウザ検証で、右操作のスラッシュキー名`SLASH`がPhaser 3.60.0では無効と判明し、`FORWARD_SLASH`へ修正しました。ResizeObserverがPhaserの準備前にrefreshして例外になる経路も防ぎました。開始位置の半径・色・反発・摩擦は実ボールへ反映します。

## 3. 検証結果

実行環境はNode.js v24.19.0、Phaser 3.60.0、Playwright 1.62.1、Chromium 153.0.8010.0です。

- `npm test`: 14/14成功。図形・MatterGameObject・World・Factory・Engineは同梱実装を使い、DOMとSceneサービスだけを代用します。
- `npm run test:browser`: 8/8成功。初回起動、入力検証、保存後のページ再読込、全種の復元、実シーン再開4回、左右キー、衝突加点、終了停止、編集復帰、マーカー削除後の再開始、リサイズ後のドラッグ、旧外周の承認／保持、容量不足、HTMLをfile://で直接開いた保存・読込を確認しました。pageerrorは0件です。
- JavaScriptの構文確認も実施しています。

通常のPlaywright用ブラウザ配布先には接続できなかったため、この環境ではnpm配布のChromium実行ファイルを展開し、`PINBALL_BROWSER_EXECUTABLE`で指定して実行しました。ブラウザテストのPhaserはCDNと同一バージョンのローカルファイルへ差し替えており、CDN障害そのものを検証したテストではありません。

## 4. 残る課題

基本経路の確認は済みましたが、次は別途検証・判断が必要です。

- 長時間プレイ、高速球、小さな物体を多数置く盤面のすり抜け・物理負荷。極端な入力サイズを含む全組合せを保証するものではありません。
- フリッパーの打感・速度・保持力の調整。角度の機械式ストッパーはなく、駆動処理による角度保持です。
- WindowsのChrome/Edge、Firefox、Safari、実タッチ端末での確認。今回の実ブラウザ検証はLinux Chromiumです。
- CDN接続がない場合の起動手段、旧データの盤面寸法を推定できない場合の扱い。
- Undo／Redo、ファイル入出力、タッチ用操作、発射装置などの採否。詳細はSPECIFICATIONの未実装一覧を参照してください。
- CIは未設定です。回帰テストはリポジトリへ追加してあり、開発者が上記コマンドで実行できます。
