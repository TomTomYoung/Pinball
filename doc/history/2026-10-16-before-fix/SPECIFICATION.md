# Pinball 現行仕様

確認日: 2026-10-16 JST  
基準: main / `24cbd761af273d1280720f61640a5afc2fa4a9a4`

本書は [index.html](../index.html) の実装を説明します。コード上の機能、現在の不具合、今後の提案を分けます。実装があることはブラウザで正常動作を確認した意味ではありません。

## 1. 構成と依存

HTML・CSS・JavaScriptをindex.htmlへ同梱しています。外部依存はCDNから読むPhaser 3.60.0で、物理エンジンはPhaserのMatter、重力は `y: 1`、debugはfalseです。ゲーム描画はPhaser.AUTOです。外部画像・音声、サーバー、モジュールビルドはありません。

画面は左70%の `phaser-container` と右30%のスクロール可能なプロパティパネルで構成します。キャンバスの初期寸法は左コンテナーのclientWidth／clientHeightです。resize時は `game.scale.resize` を呼びますが、盤面オブジェクトや境界壁の再配置はありません。

主なクラスと責務は次です。

- `PinballGame`: Phaser.Game生成、DOMボタン、シーン切替、テスト用layoutData。
- `GameObject`: 共通属性、選択表示、位置・色・反発の更新、serialize／deserialize。
- `Wall`、`Bumper`、`Flipper`、`Ball`: 描画とMatterボディ、種類別属性。
- `EditorScene`: objects配列、追加・選択・ドラッグ・編集・削除、保存・読込。
- `GameScene`: レイアウト復元、ボール生成、キー入力、衝突加点、落下判定。

`backup` と `backup2` は実行時に参照されません。現在の変更先をバックアップへ取り違えないでください。

## 2. エディター

起動するEditorSceneは左・右・上の3境界壁を作ります。下側に床はなく、プレイ時は落下できる設計です。初期レイアウトにバンパー・フリッパー・発射位置はありません。

追加ボタンは壁を `(200,200)`・100×20、バンパーを `(200,200)`・直径相当40、フリッパーを `(150,画面高さ−100)`・100×20、開始位置マーカーを `(200,200)`・半径10で生成します。開始位置マーカーは既存の一つを削除して置き換えます。クラス名や引数名にradiusとありますが、Bumperコンストラクターの第4引数は実際には直径相当で、内部radiusはその半分です。

オブジェクト一覧から選択でき、選択中は黄色の線で強調します。キャンバスでの選択は形状との当たり判定ではなく、保存座標からの距離が50未満のうち最も近いオブジェクトを選びます。回転した長い壁の端をクリックして選択できる仕様ではありません。ドラッグはクリック時の位置差を維持します。何も選ばない場所のクリックで選択解除します。

共通の編集項目は名前、X・Y、幅・高さ、反発係数、色です。壁には角度、バンパーには得点、フリッパーには初期角度・フリップ角度・左右の項目があります。数値はparseFloatで代入し、有限値・正の寸法等のモデル側検証はありません。反発係数の入力欄には0〜1・刻み0.1が指定されていますが、バンパーのクラス既定値は1.5です。

境界壁を編集・削除・保存から除外する分岐は `type === 'boundary'` に依存します。しかしWallがtypeをwallに固定し、渡されたoptions.typeを保持しません。現在は境界壁も一覧・編集・保存対象となります（STATUS P-02）。

## 3. オブジェクトと物理

### Wall

長方形の描画とMatterボディです。データ上のisStaticの既定値はtrue、反発係数は共通既定値0.7です。updatePropertiesは位置、表示寸法、角度、ボディスケールを更新します。ただしisStaticを設定する前にcreateGameObjectが実行されるため、実際のボディへ意図した静的属性を渡せていません。

### Bumper

円形の描画と静的ボディを生成します。派生コンストラクターの最終値は反発係数1.5、得点50、青 `#00aaff` が既定です。これらの設定とradius設定が描画・ボディ生成より後になる問題があります。

ボールとのcollisionstartで得点を加え、黄色にフラッシュして100ms後に戻すコードがあります。得点は `score || 50` を使うため、0を設定しても50扱いになります。

### Flipper

長方形の静的ボディです。最終データの既定値は左フリッパー、初期角度0度、フリップ角度−45度、反発係数0.8、赤 `#ff0000` です。右指定で新規構築した場合のフリップ角度既定値は+45度です。

flip／resetで角度を即座に切り替えます。Matter.Constraintによるヒンジ、トルク、角速度駆動はありません。描画のorigin変更があるだけなので、物理的な支点固定と一致するかは未検証です。生成時はisLeft・currentAngle等がまだ未初期化です。編集でrestAngleを変えてもcurrentAngleへ直ちにコピーする処理はありません。

### Ballと開始位置マーカー

実ボールの生成半径は10、派生側の反発既定値は0.8、friction既定値は0.005、frictionAir指定は0.001、色既定値は白です。ただしradius・friction・markerフラグ等を設定する前に描画・物理生成が呼ばれます。特にマーカーを非物理・半透明にする分岐はフラグが未定義の時点で評価されます（STATUS P-01）。

マーカーはレイアウト復元時にX・Yだけを開始位置として利用し、ゲーム側のボールは新しく半径10で作ります。マーカーのサイズ、色、反発は実ボールへ引き継ぎません。マーカーがない場合の開始位置は画面幅の1/2、高さの1/3です。

初速度はXが `Math.random() * 4 - 2`、Yが−5です。seed保存や発射ボタンはありません。

## 4. テストプレイと操作

テストプレイでEditorSceneのレイアウトを取得し、EditorSceneをpauseしてGameSceneを開始します。保存・読込ボタンを隠し、右パネルのpointer-eventsをnoneにします。GameSceneは3境界壁を新規に作り、保存レイアウトの物体を復元して実ボールを追加します。現在はレイアウトにも境界壁が含まれるため、境界が二重になる問題があります。

左フリッパーは左矢印またはZ、右フリッパーは右矢印またはスラッシュで操作します。キーを押している間はflip、離すとresetです。画面上のタッチ用フリッパーボタンはありません。

ボールとバンパーの衝突でバンパー得点、動作中フリッパーとの衝突で10点を加えます。ボールが `game.config.height + 50` より下へ落ちるとGame Overを表示します。残機や複数球、ステージクリアはありません。

ゲーム終了処理はボール速度を0にするだけで、物理world停止・isGameOver状態・入力停止はありません。そのため終了後の更新停止を保証していません。もう一度ボタンはGameSceneをrestartする意図のコードです。実際の呼出し先はgame.sceneで、API適合性はSTATUS P-03の確認事項です。編集へ戻るボタンはGameSceneのstopとEditorSceneのresumeです。再開時のscore・objects・開始座標のリセットはinit／createに実装されていません。

## 5. 保存形式

ブラウザlocalStorageの `pinballLayout` 一枠にJSON文字列を保存します。保存は手動のみで、ページ起動時の自動ロードはありません。JSONファイルのimport／export、複数スロット、共有はありません。

トップレベルは `objects` 配列のみで、schemaVersion、盤面サイズ、IDはありません。各物体は次の共通属性を保存します。

```json
{
  "objects": [
    {
      "type": "wall",
      "x": 200,
      "y": 200,
      "width": 100,
      "height": 20,
      "angle": 0,
      "name": "Wall",
      "restitution": 0.7,
      "color": "#888888",
      "isStatic": true
    }
  ]
}
```

WallはisStatic、Bumperはradiusとscore、FlipperはisLeft・restAngle・flipAngle、Ballはradius・isBallPositionMarkerを追加します。Ballのfrictionは保存されません。スコア、速度、進行中のゲーム状態、選択状態も保存しません。

読込はJSON.parse後に既存物体を削除し、その後objectsを順番にdeserializeします。typeが未知ならconsole.errorを出してその物体を飛ばします。例外はalertへ変換しますが、全データを検証してから一括置換する処理ではなく、途中失敗時に編集内容を復元できません。localStorage.setItemの例外は保存側で捕捉していません。

## 6. 未実装と仕様上の保留

Undo／Redo、複数選択、複製、スナップ、回転ハンドル、形状に沿う選択、JSONファイル出力、盤面寸法の固定・保存、タッチ操作、音声、残機、発射装置、seed、テスト基盤はありません。

これらは現状の欠落一覧であり、自動的に採用が決まった機能ではありません。まず現行の物体生成と編集→保存→プレイの往復を直します。今後の保存形式、寸法変更、物理支点の決定事項はHANDOFFへ追記してください。
